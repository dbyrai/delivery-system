# Kiro Integration Prompt

```text
Set up the optional Kiro workflow add-on for this Delivery System project.

Read the applicable project instructions, addons/kiro/README.md, its record and
steering template. Inspect the working tree, existing .kiro/ steering and specs,
and the documentation root. Preserve existing rules, completed project documents,
stable IDs, and unrelated changes. Do not overwrite a different steering file.

Confirm the Kiro surface/version, accountable owner, intended native-spec usage,
and whether live verification is available. Show conflicts and open decisions
before writing. After confirmation, reconcile the template into
.kiro/steering/delivery-system.md, complete the durable record at
<docs-root>/project/integrations/kiro.md, and add one short conditional pointer
from the canonical shared instructions for Kiro-related work.

If native specs are used, map requirements, design, and tasks reciprocally to the
authoritative project files. Do not generate unsolicited specs or treat generated
content as approval. Keep existing bootstrap, security, ownership, question, and
acceptance gates.

Activated files must not reference addons/. Do not install Kiro, MCP servers,
hooks, services, external integrations, or custom agents. Verify paths, links,
front matter, repeatability, and - when available - actual loading in a fresh
Kiro conversation. Record unavailable live checks as pending. Activation grants
no authority to commit, push, merge, publish, or change external systems.
```
