# Kiro Deactivation Prompt

This prompt also works independently after the optional package was removed.

```text
Deactivate the Delivery System Kiro add-on in this project.

Read applicable instructions and the existing project integration record. Inspect
the working tree, installed steering, selected custom-agent resources, routing,
and mapped native specs. Preserve unrelated changes and Kiro configuration.

Identify native changes or acceptance evidence missing from authoritative project
documents. Obtain a focused decision on unresolved migration/retention choices,
then reconcile and verify required content before removing steering needed for
the handover. Preserve specs, history, IDs, and evidence unless deletion is
explicitly authorized. Report unresolved handover as incomplete.

Remove only add-on-owned steering and conditional routing within this request.
For customized shared files, remove only the agreed add-on content. Preserve
shared instructions, roles, AGENTS.md, other steering, MCP access, and external
integrations. Update the durable record with retained artifact paths, source
authority, changes, and verification. Deleting optional addons/ files is separate
from deactivating installed steering.

Verify paths and links and use a new Kiro conversation to confirm the add-on's
steering is no longer loaded. AGENTS.md may still load the core workflow; do not
claim Kiro itself is disabled. Record an unavailable live check as pending.
Report the changed files, knowledge handover, retained settings, and remaining
checks. Do not commit, push, publish, or send messages without authorization.
```
