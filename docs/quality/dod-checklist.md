# Definition Of Done Checklist

Use this checklist before marking a spec, task, or deliverable complete.

## Requirement Fit

- [ ] Work matches the linked requirement or spec.
- [ ] Scope changes are documented.
- [ ] Source requirement/spec open questions, unresolved points, and linked question files are resolved or explicitly deferred before task creation.
- [ ] Task open questions, unresolved points, and linked question files are resolved or explicitly deferred before implementation.
- [ ] User decisions from step-by-step question resolution are documented.

## Implementation Quality

- [ ] Existing project patterns are followed.
- [ ] No unrelated refactors are included.
- [ ] Error, empty, and edge states are handled where relevant.
- [ ] Secrets and sensitive data are not committed.

## Documentation

- [ ] Relevant docs are updated.
- [ ] New configuration or commands are documented.
- [ ] Decisions with future impact are recorded.

## Verification

- [ ] Relevant automated tests pass, if available.
- [ ] Build/type/lint checks pass, if applicable.
- [ ] Manual checks are documented, if needed.
- [ ] Known limitations and risks are listed.

## Handoff

- [ ] Changed files are summarized.
- [ ] Verification evidence is included.
- [ ] Follow-up tasks are captured.
- [ ] Responsible next owner is clear.
